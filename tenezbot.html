Independent Project

TenezBot

A robot that plays fetch: it detects and collects tennis balls from a court.

Robotics Agile & TDD 2020

TenezBot detects and collects tennis balls scattered across a court, built for a client, Acme Robotics, as a deliverable software package rather than a one-off demo, and run less like a solo robotics project and more like a small software team would run it.

TenezBot on court

Automating court cleanup

After a practice session, tennis balls end up scattered across the court, and gathering them by hand is exactly the kind of repetitive task worth automating. TenezBot was built for Acme Robotics as, in the project's own framing, "a complete software package which will be integrated in their new line of products," rather than a standalone one-off robot.

How it works

The robot runs a simple sense-plan-act loop, repeated until the court is clear: spot a ball, figure out how to reach it, drive there, pick it up, then look for the next one.

Platform

A TurtleBot base fitted with a custom-built ball collector attachment.

Sensing

A vision camera detects tennis balls in frame and estimates distance to the nearest one.

Planning

A path-planning algorithm converts that detection into a route to the target ball's coordinates.

Collection

The collector attachment picks the ball up into an attached sac, then the loop repeats on the next target.

Built the software way

Most of my other independent projects were single-pass builds: design it, build it, see if it works. TenezBot was a deliberate departure from that, run with an Agile, iterative process and test-driven development instead. Detection and collection behavior were built incrementally against tests written first, with each iteration adding one capability, spot a ball, drive to it, pick it up, rather than trying to get the whole pipeline working at once. The design itself was documented the same way a software team would, with activity and class UML diagrams laying out the system before the code did.

Where it stands
