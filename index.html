Systems Engineer, Miso Robotics

I work at the boundary between mechanical, electrical, firmware, and software: the layer where most of the interesting failures actually happen. I write the requirements and interface contracts that let cross-functional teams build the same system without building against each other, then run the verification and validation that proves it works.

Before Miso, I built the autonomy stack for an electric scooter at the University of Maryland and a multi-domain surveillance robot for DRDO. Outside of work, I still read failure-mode analyses for fun.

What I do

Requirements & architecture

Authoring the requirements and interface contracts that let mechanical, electrical, firmware, and software teams build the same system without building against each other.

Verification & validation

Turning "does it work" into a plan: hardware-in-the-loop rigs, automated test suites, and staged fleet validation before anything reaches production.

Functional safety

Hazard analysis and risk assessment that holds up to certification, most recently achieving Performance Level d under ISO 10218.

Right now: building the systems engineering function at Miso Robotics from the ground up: requirements management, V&V planning, and release readiness for a commercially deployed robot.
